# Obstacles in structures and templates
How to put [class-gated obstacles](../systems/obstacles.md) into a structure: from structure-piece code with `ObstaclePlacer`, or in NBT templates and jigsaw pieces with the `dndclasses:obstacle_tier` processor. This page is for dungeon and structure authors.

## How it works
### From piece code
- `ObstaclePlacer.place / doorway / box / chasm / winch` write obstacle blocks and their block entity data. Like chest loot, a block is only written when the `chunkBox` passed to `generate` contains it, so a piece that spans chunks writes each block exactly once, from the chunk that holds it.
- Every block of one obstacle group must get the same group seed in every chunk. Draw it from the piece's own seeded random (drawn whether or not the block is in this chunk), or use `StructureObstacles.seedAt(pos)`, which only depends on the position.
- Add new obstacles at the **end** of a piece's `generate`, or from a separately seeded random, so the earlier random draws don't change. A structure half-generated by an older version then still matches up across its chunk borders.
- Dwarven fortress pieces have `FortressPiece.Builder.obstacle(x1, y1, z1, x2, y2, z2, type, tier, critical)`, in the piece's local coordinates.
- `StructureObstacles.guardianPost(world, chunkBox, post, type, spots, count, tier, critical)` places a Guardian Beast post and spawns its beasts already bound to it, so they can't wander off unbound before a player arrives.
- A `critical` obstacle sits on the structure's main path, so its type needs a fallback that works solo. Of the placements below, only the goblin camp's Guardian Beast post is critical (fallback: fight the wolves).

### In NBT templates and jigsaw pieces
Obstacle blocks keep their block entity NBT when a structure block saves them: `Tier`, `Critical`, `GroupSeed`, `ResealTicks` and `Data`. Paint obstacles with `/dndobstacle place` (each call gives its group its own seed), save with a structure block, then place the template with the processor in its processor list:

```json
{
  "processors": [
    { "processor_type": "dndclasses:obstacle_tier", "depth": 3 }
  ]
}
```

| Field | Effect |
|-|-|
| `tier` | `easy`, `medium`, `hard` or `very_hard` for every obstacle in the template |
| `depth` | Used when `tier` isn't set: the tier for a dungeon floor's depth. 0 or less is Easy (DC 10), 1-2 Medium (DC 13), 3 and deeper Hard (DC 15). Very Hard (DC 18) is only ever set with `tier` |
| `critical` | Optional: overrides every obstacle's saved `Critical` flag |

With neither `tier` nor `depth`, the tier saved in the template stays (Medium if it has none). The processor always mixes each group's saved `GroupSeed` with the placement's origin. Two copies of a template that touch stay separate groups, and the groups inside one copy stay as you painted them.

## Where to find it
The placements in the mod's structures and vanilla ones are listed in [Class-gated obstacles](../systems/obstacles.md#where-to-find-it).

## Commands
- `/dndobstacle template <template> <pos> [<tier> | depth <n>]` (op level 2) places a structure template through the processor, the way a dungeon would. With no tier it keeps the tiers saved in the template.

## Known limitations
- A group that spans two jigsaw pieces gets a different seed in each piece, so it opens as two groups.
- The processor only rewrites obstacle blocks. Containers and mobs in the template are placed as saved.

## For developers
- `classes/Obstacles/ObstacleTierProcessor.java`: the processor, its codec, `tierForDepth(depth)` and `rewrite(nbt, origin)`. It's registered from `ObstacleTypes.register()`.
- `classes/Obstacles/StructureObstacles.java`: `seedAt(pos)`, `guardianPost(...)` and `placing()`, the structure start whose pieces this thread is generating (set by `mixin/StructureStartPlacingMixin`), so a vanilla piece's mixin can check its sibling pieces.
- Devscripts:
  - `obstacle-placements.txt` saves a template with a structure block and places it through the processor at depth 3, at `very_hard` and as saved; checks the Lich's half-health dead beside a consecrated altar; and places strongholds, mineshafts and a Nether fortress with `/place structure` and lists their obstacles.
  - `/place structure` fails for the mod's terrain-checked structures, so `obstacle-placements-locate.txt` finds natural ones in unexplored land, `obstacle-placements-tour.txt` generates them and lists their obstacles, and `obstacle-placements-shots.txt` screenshots each one (coordinates for the dev world's seed).
